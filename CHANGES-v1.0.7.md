# SNDT v1.0.7

## New
- Landing page at sndt.cc (user request 2026-11-15; look matches the app: paper, ink, hazard red, Archivo Black, hard offset shadows; tagline "Draw the network in your head."). Source `src/landing.html`, screenshots in `src/landing-img/` (made from the v1.0 showcase shots). Sections: hero with the editor screenshot, three numbered features (lanes, timeline video, isolated line view), an eight-cell "everything else" grid, phone, Minecraft servers, community (Discord, GitHub, Ko-fi), a closing call and a footer. Works in dark mode and at phone width (no sideways scroll at 390px).
- The editor moved from sndt.cc/ to sndt.cc/app/. Nothing old breaks: the landing page sends share links (`?m=`), handbook demos (`?embed=1`), sign-in returns (`?code=`), live-session links (`#join=`), tutorial and search links (`#tutorial=`, `#search=`) and the installed app straight on to /app/ with everything after the address kept. New sign-ins return to /app/ by themselves (the redirect address is the page's own path).
  - `scripts/build.py`: when building into an `app/` folder, the editor's root-relative paths (`fonts/…`, `handbook/`) become absolute; the page description now says "a free editor for transit maps of any city, real or imagined".
  - Handbook: "Open SNDT", tutorial links and the live demos point at /app/.
  - Installed app: `start_url` is /app/; the service worker caches /app/ too (cache `sndt-v4`) and falls back to the editor when offline.
  - `scripts/deploy.sh` builds the editor into `site/app/`, copies the landing page to `site/index.html` and its pictures to `site/img/` (both git-ignored, like the other built files).
- Later: refresh the screenshots with the v1.0.6 header, translate the page.
- Background images (SlimboAmingon, Discord "custom bg (image importing)", 2026-11-12): an image's Layer can now be "Background, behind everything". It is drawn under the water, parks and areas in the editor, exports, the timeline and the video. In the editor it sits in the `#under` layer (`#backL`, `renderBack()`), so it can't be clicked on the map and doesn't get in the way of drawing over it; This map lists the background images as buttons that select them (`sel-img`), and their X/Y fields show in Simple too.
- Facility icons per station (Curt, Discord "Local facility options for each station", 2026-11-12): a station with facilities has its own "Facility icons" (top, centre, bottom or As the map) and "Icons per row" (empty = as the map) under Icon size (`s.iconAlign`, `s.iconRow`, read through `stIconAlign()` / `stIconRow()`).

- What's new popup + public changelog (Plentk's idea, 2026-11-15): after an update, players who have used SNDT before see "What's new in SNDT x" once (`WHATSNEW` {v, items} next to `modal()`, seen version in localStorage `sndt:whatsNew`; first-time players get the tutorial and are marked as seen; never in embed mode). "Full changelog" opens sndt.cc/changelog/; Help › What's new opens it again. The page is built by `scripts/changelog.py` from every `releases/vX/CHANGELOG.md`, newest first, with a version list at the top (deploy.sh runs it; `site/changelog/` is git-ignored; the service worker caches it under its own key). The landing page links it in the header and footer. **Update `WHATSNEW` and write the release's CHANGELOG.md with every release.**
  - What's new › Full changelog and Help › Changelog open sndt.cc/changelog/ in a new tab (`CHANGELOG_URL`). An in-app changelog dialog was tried first and dropped at the owner's request (2026-11-15).
  - The sndt.cc/changelog/ page is the same list (owner request 2026-11-15): every version since v1.0, newest open, the others as rows to click open (`<details id="v1-0-6">`); a link with #v1-0-6 opens and scrolls to that version. A table of contents on the right lists every version, stays in view while scrolling, and marks the open ones with a red square; on phones it becomes a row of links above the list (owner request 2026-11-15). Only exists on sndt.cc after the v1.0.7 deploy. Tested headless: no popup on a first visit, popup once for a returning player, not again after a reload.

## Fixes
- Area outlines touch again with the gap between areas at 0 (Curt, Discord "Outlines on districts do not touch each other", 2026-11-12; also ROADMAP v1.0.7 "hairline seam"). The v1.0.6 fix cut an area's outline 3 wider than the area in front of it, which left a visible break; the cut is now exactly the 1.5 an outline reaches outside its area (a hair less at gap 0 so they overlap). Checked on curt-tung-sha-2 (the CHTR title box): the break at the top edge is gone.

- Label background (station `lbg`): the box now has even padding round the visible text (from the first row's cap height to just under the last row's baseline) instead of extra room on the right and below, which left the text high and to the left; a facility icon beside a label with a background is centred on the box (owner comment on the preview, 2026-11-15). Checked on curt-tung-sha-2 with every station given a background.
- Facility icons sit a little further from the station name (5 instead of 3–4; with a background, 3 from the edge of the box; first tried 6 + padding, which the owner found too far), so they no longer touch the box (owner comment on the preview, 2026-11-15).
- Manual layout: the white corner circles of a picked part can be clicked. That makes the segment a hand-drawn route (`makeCustom`) with a bend point at that corner and selects it, so its Scratch-style curve handles show: drag a handle to bend the line through the point, double-click one for a sharp corner again (Curt, Discord "This thing for a track segment", 2026-11-12). Three follow-up fixes for the anchor jumping when bending (circle on the anchor, a frozen on-screen spot, handles seeded from a smooth curve) were tried on 2026-11-15 and reverted at the owner's request: this first version is what stays. Known: on a smooth segment, the first handle drag still turns the curve into straight lines plus one bend.
- Bend point handles can be typed in (owner request 2026-11-15): with a bend point picked, Selected segment shows "Bend point N" with Angle ° (0 = right, 90 = up) and Handle length; typing an angle on a sharp point gives it handles 30 long along that angle, length 0 or empty makes it sharp, and "Sharp corner" removes the handles (`bendField()`, `bend-ang` / `bend-len` inputs, `bend-sharp`). Picking a bend point now refreshes the panel. Tested headless: 45° gave a handle of (21.21, −21.21), length 30.
